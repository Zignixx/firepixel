## Für die Nachprüfung (NACHPRUEFUNG)

1. Verlaufsgriffe: Rechteck, Füllung Verlauf, Zeiger. Endgriff (Quadrat) ziehen → Verlauf dreht/streckt sich live,
   Verlauf-Bedienfeld: genau ein Schritt; Strg+Z stellt ihn zurück. Bei Ellipse/Rechteck-Verlauf den Griff der
   zweiten Achse ziehen → nur die Breite ändert sich. Erwartung: wie oben; im Original den runden Griff ziehen und
   vergleichen (verschiebt er alles?).
2. Gamma: Neues Dokument mit transparenter Leinwand, Ansicht ▸ Gamma → Schachbrett heller; 2-fach/4-fach → Kacheln
   ebenfalls heller, Ausschalten → zurück.
3. NACHPRUEFUNG §1 (Pinsel, Esc): Zeile auf „Esc im Zug bricht nicht ab, danach Zeiger + Schritt Bitmapmodus
   beenden“ umstellen (BA-038, Doku-Agent).
4. Verbinden mit einem benannten offenen Pfad → geschlossen, Name in Ebenen leer; mit benanntem Rechteck → keine
   Meldung, Name leer.
5. In Bitmap konvertieren: sichtbares Rechteck + mitgewähltes Rechteck mit Füllung Alpha 0 → Bitmap-Grenzen nur das
   sichtbare Rechteck.

## Neue Befunde

1. **In Bitmap konvertieren ignoriert die Deckkraft der Objekte** (`render_elements` liefert das Aussehen vor
   Deckkraft/Mischmodus, beide Renderer): ein mitgewähltes Objekt mit Deckkraft 0 wird deckend gerastert. B-2 hat im
   Original mit Deckkraft 0 gemessen: das Objekt fällt weg (Zuschnitt auf 150,200–200,250). Offen, ob das Original
   die Deckkraft einbäckt oder bei einem einzelnen Objekt als Eigenschaft behält → wartet auf B-2, dann
   `crates\fp-engine\src\render_backend.rs` und `crates\fp-ui\src\canvas\render.rs` `render_elements`.
2. Verlaufsgriffe: während des Ziehens zeichnet die Leinwand die alten Griffe weiter (aus dem Dokument) neben der
   Vorschau des gezogenen Griffs – kosmetisch, beim Loslassen weg.
